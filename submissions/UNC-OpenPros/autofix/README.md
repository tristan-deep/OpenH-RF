# OpenH-RF Sub-Dataset: Limited-View Prostate Ultrasound Computed Tomography (OpenPros)

## Dataset Description

Pre-beamformed channel-domain ultrasound waveforms from **simulated limited-view
prostate ultrasound computed tomography (USCT)**, paired with voxel-level
ground-truth **speed-of-sound (SOS)** maps. Each acquisition models a
transabdominal/transrectal pair of opposing apertures: sources and receivers are
placed on two parallel lines bounding a 60 mm × 150 mm sagittal panel — one at
the body surface, one at the rectal wall — giving a strongly limited angular
coverage compared with a full ring array.

All data are **synthetic** (forward-modelled); no human or animal subjects are
involved. The dataset accompanies the OpenPros paper (ICLR 2026) and targets
learned full-waveform-inversion-style SOS reconstruction from limited-view data.

## Dataset Format

Packaged in the **`zea` HDF5 file format** (`zea` v0.1.2), one `.hdf5` file per
acquisition, written through `zea.File.create` by
[`convert.py`](../convert.py). Raw channel data lives at
`tracks/track_0/data/raw_data`, acquisition parameters at
`tracks/track_0/scan`, aperture geometry at `probe`, and the ground-truth SOS
map at `tracks/track_0/data/sos_map` with per-pixel `coordinates`.

**Transmit-block layout.** The source `.npy` arrays store four blocks of 10
transmits each — surface→surface (SS), surface→rectum (SR), rectum→rectum (RR),
rectum→surface (RS). `convert.py` folds these into the zea
`(n_frames, n_tx, n_ax, n_el, n_ch)` layout by placing the two source sides along
`n_tx` and the two receiver sides along `n_el`. Elements `0:161` are the surface
aperture and `161:322` the rectum aperture; transmits `0:10` fire from the
surface side and `10:20` from the rectum side. `custom_ops.MyRearrange` inverts
this folding for the network.

**Pre-processing applied before packaging:** none — the stored waveforms are the
raw simulation output at the native sampling rate. No demodulation, decimation,
or beamforming.

## Data Validation

[`reconstruct.py`](../reconstruct.py) reconstructs the SOS map from the raw
channel data with a `zea.Pipeline`:

```
MyRearrange -> LogTransform(k=1e5) -> Normalize(-1, 1)
            -> InversionNetSOS -> Normalize(1300, 3600)
```

`MyRearrange` restores the four SS/SR/RR/RS acquisition blocks the network
expects, `LogTransform` applies the sign-preserving `log1p` compression used by
the official OpenPros implementation, and `InversionNetSOS` runs the pretrained
InversionNet (20,447,515 parameters). The prediction is mapped from `[-1, 1]`
back to the physical range 1300–3600 m/s. The pipeline is saved to
[`pipeline.yaml`](pipeline.yaml).

The reference figure [`pred_sos.png`](pred_sos.png) shows the ground-truth and
predicted SOS maps side by side over the 60 mm × 150 mm panel, displayed on a
1300–1700 m/s window.

## Known Issues

- **`t0_delays` and `tx_apodizations` are all zeros.** Transmissions come from
  external point sources rather than from elements of the receive aperture, so
  per-element delays and apodization weights do not apply. The physical transmit
  information is carried entirely by `scan/transmit_origins`. A downstream user
  who feeds this file to a standard delay-and-sum beamformer without reading this
  note will get an empty image.
- **Aperture positions sit 0.25 mm outside the SOS-map grid.** Sources and
  receivers are placed on the 3× upsampled forward-modelling grid, whose extent is
  `(3n − 1)·(dx/3)` = 60.25 mm × 150.25 mm, while the SOS map spans
  `(n − 1)·dx` = 60 mm × 150 mm. REQUIRES_CONTRIBUTOR: confirm which grid is
  authoritative.
- **Display window vs stored range.** `reconstruct.py` maps the network output to
  1300–3600 m/s but displays 1300–1700 m/s, so the bony structure saturates white
  in the reference figure. This is a display choice, not clipping in the data.
- REQUIRES_CONTRIBUTOR: any solver-specific artifacts (numerical dispersion,
  boundary reflections, absorbing-layer leakage) a user should be aware of.
